# JanaМен — карта экранов

Статус: готовы `/login`, AppShell и сквозной сценарий отпуска: кабинет, профиль,
создание, реестр, детальная заявка, очередь руководителя и уведомления. Academy,
AI Jana и HR показывают общую заглушку; неизвестный URL в демо — 404.
`/` ведёт ко входу или в начальную область выбранной роли. Роль хранится в
sessionStorage вкладки, бизнес-данные — в едином localStorage `jana.mock-state.v1`.
Это демонстрация без сервера и защищённой сессии. `:requestId` — UUID реальной mock-записи.

## Основные маршруты

**Все** — Employee, Manager, HRAdmin со своей личной областью; **Manager** — только
разрешённая команда; **HRAdmin** — только назначенная область HR. Иерархия ролей
не предполагается: HRAdmin не получает произвольные права руководителя.

| URL | Экран | Роль / область | Основные переходы |
| --- | --- | --- | --- |
| `/` | Начальная точка | Публично, без данных | Вход либо домашний маршрут выбранной роли |
| `/login` | Демонстрационный вход | Без выбранной роли | Employee → `/dashboard`, Manager → `/manager/approvals`, HRAdmin → `/hr` |
| `/dashboard` | Личный кабинет | Все / своё | Профиль, новая заявка, история, Academy, AI, уведомления |
| `/profile` | Профиль | Все / своё | Кабинет; кадровые поля read-only |
| `/requests` | Мои заявки | Все / своё | Новая заявка, карточка и история |
| `/requests/new/leave` | Оформление отпуска | Все / своё | Проверка → отправка → `/requests/:requestId` |
| `/requests/:requestId` | Заявка и история | Все / своё | Статус, история, возврат к списку |
| `/notifications` | Уведомления | Все / своё | Связанная заявка или курс |
| `/academy` | Jana Academy | Все / назначенное | Назначенный курс |
| `/academy/:courseId` | Обзор курса | Все / назначенное | Материал, продолжить, результат |
| `/academy/:courseId/lessons/:lessonId` | Материал / проверка знаний | Все / назначенное | Следующий материал или результат |
| `/academy/:courseId/result` | Прогресс и результат | Все / своё | Курс, Academy, кабинет |
| `/ai-jana` | HR-ассистент | Все / разрешённая база | Источник или обращение в HR |
| `/knowledge/:articleId` | Источник | Все / разрешённый документ | Назад к AI Jana |
| `/manager/team` | Моя команда | Manager / своя команда | Согласования; разрешённые сведения |
| `/manager/approvals` | Очередь согласования | Manager / своя команда | Решение по заявке |
| `/manager/approvals/:requestId` | Просмотр и решение | Manager / своя команда | Согласовать / отклонить с причиной → очередь |
| `/hr` | Рабочее пространство HR | HRAdmin / область HR | Реестр, сотрудники, обучение, знания |
| `/hr/requests` | Реестр заявок | HRAdmin / область HR | Подробности заявки |
| `/hr/requests/:requestId` | Обработка заявки | HRAdmin / область HR | История, состояние будущей интеграции |
| `/hr/employees` | Сотрудники | HRAdmin / область HR | Read-only сведения; детали в боковой панели |
| `/hr/learning` | Назначение обучения | HRAdmin / область HR | Назначение → уведомление сотруднику |
| `/hr/knowledge` | База знаний | HRAdmin / область HR | Документы, разрешённые источники AI |
| `/forbidden` | Нет доступа | Системный экран | Разрешённая область |
| `*` | 404 | Все в демо | Вернуться в свою область |

Техническая основа сохранена по адресу `/__foundation`, только в dev-режиме.
HR-формы, контакт HR и тестирование курса реализуются отдельными задачами.

Motion-этап не добавляет бизнес-маршрутов и не меняет операции. AppShell остаётся
постоянным при переходах, меняется только Outlet. На `/dashboard` и деталях заявки
Jana Flow Map — интерактивный SVG-маршрут. Выбор станции раскрывает пояснение,
не выполняя кадрового действия. Только сохранённое событие запускает Living Route;
при обычном переходе между экраном заявки и кабинетом оно не повторяется.
Фильтр уведомлений и выбор решения используют один SegmentedControl с native radio.

## Реализованные переходы оболочки

- Выбор роли нативными radio (Tab/стрелки) → «Войти в пространство» → начальный раздел.
- Боковая навигация/мобильный dock → выбранный раздел с активной меткой.
- Bell с числом непрочитанных → `/notifications`; просмотр и отметка о прочтении.
- Меню профиля → `/profile`, смена роли или выход. Выход очищает demo-role из вкладки.
- Без demo-role рабочие URL ведут на `/login`; несовместимая роль → `/forbidden`.
  Это UX-поведение, не безопасная серверная авторизация.
- Мобильное «Все разделы» → modal navigation; Escape/закрытие возвращают focus.
- Обновление страницы сохраняет выбранную роль в пределах вкладки; при недоступном
  sessionStorage демо работает в памяти до обновления. Пароли и токены не используются.

## Главный сквозной сценарий

```mermaid
flowchart LR
  A[Employee: кабинет] --> B[Заявка на отпуск]
  B --> C[Проверка дат и подтверждение]
  C --> D[Submitted: заявка + история]
  D --> E[Manager: очередь своей команды]
  E --> F[Просмотр заявки]
  F --> G{Решение}
  G -->|Согласовать| H[Approved]
  G -->|Отклонить с причиной| I[Rejected]
  H --> J[История + уведомление Employee]
  I --> J
  J --> K[Employee: результат в карточке]
```

Для минимального демо согласование Manager завершает пользовательский путь.
HR-обработка и передача в Documentolog не становятся скрытым дополнительным
обязательным согласованием. При появлении такого требования расширить модель явно.

Локальное заполнение формы не равно созданной заявке. Отправка создаёт Submitted;
решения: Submitted → Approved или Submitted → Rejected. Причина отказа обязательна.
Cancelled зарезервирован для отдельного сценария отмены и пока не имеет команды/экрана.
Повторное решение и stale version дают conflict. Заявка, событие истории и уведомление
относятся к одной операции. Mock-адаптер выполняет один setItem для заявки, истории и
уведомления; Web Locks сериализует операции вкладок, storage events обновляют UI.
Без Web Locks гарантируется последовательность в одной вкладке; конкурентное демо
в нескольких вкладках следует запускать в поддерживаемом Chrome.

Реестр поддерживает поиск по номеру (в Manager также по сотруднику), фильтр статуса,
сортировку по созданию или началу отпуска. Manager Queue открывается на Submitted;
«Все статусы» показывает завершённые решения. Read-only профиль показывает баланс:
24 минус календарные дни Approved. Submitted не резервирует дни; сервис повторно
проверяет остаток при согласовании. Отмена не реализована.

## Другие сценарии

```mermaid
flowchart LR
  A[Назначение HR] --> B[Уведомление]
  B --> C[Курс]
  C --> D[Материал / тест]
  D --> E[Прогресс / результат]
  E --> F[Кабинет + уведомление]
  G[Вопрос AI Jana] --> H{Есть разрешённый источник?}
  H -->|Да| I[Ответ + ссылка на документ]
  H -->|Нет| J[Нет надёжного ответа + обращение в HR]
```

## Системные состояния и доступ

- Без сессии → вход; прямой URL чужого объекта не даёт данные.
- Неподходящая роль/область → forbidden или согласованный not-found без раскрытия объекта.
- Каждый список: loading, empty, error/retry и успешное состояние.
- Форма: untouched, validation errors, submitting с защитой от повтора, success, conflict.
- При потере связи не показывать успешную отправку, решение или завершение курса.
- Notification ведёт к объекту с повторной проверкой доступа. Прочитано не равно удалено.
- История использует реальные события, не вымышленный анимированный прогресс.
- UI скрывает недоступные действия для понятности; backend проверяет роль, владение,
  принадлежность команде и каждый переход. Сейчас эти проверки реализованы только
  в mock-сервисах и не защищают от изменения пользователем localStorage.

## Последовательность будущих этапов

1. Продуктовая оболочка, навигация и кабинет Employee — готовы.
2. Создание отпуска, список и история с явным demo-адаптером — готовы.
3. Manager: очередь, решение, результат и уведомления Employee — готовы.
4. Academy: курс, материал, прогресс, результат.
5. AI Jana: база знаний, источники и отсутствие ответа.
6. HR: реестр, сведения, назначения и знания.
7. ASP.NET Core + PostgreSQL и серверная авторизация отдельной задачей.

Это карта развития, а не разрешение реализовать следующие этапы автоматически.
