# JANA FLOW

**Human-Centered Operations Interface.** Внутренняя HR-платформа, где человек
понимает своё положение в процессе и следующее действие. Референсы языка: Swiss
International Typographic Style, editorial design, транспортная навигация и
профессиональные операционные интерфейсы.

Статус: реализованы экран демо-входа, оболочка и рабочий сценарий отпуска.
Направление — **JANA FLOW / Editorial Operations**; исходная палитра и сетка сохранены.

## 1. Композиция

- Главный объект экрана — задача человека, а не набор метрик.
- Заголовок, контекст, рабочая область и следующее действие образуют ясную иерархию.
- Использовать асимметрию 8/4 или 7/5, сохраняя общие линии выравнивания.
- Отступы и тонкие разделители группируют содержимое. Карточки нужны только для
  отдельного контекста или действия; таблицы, списки и история не обязаны быть карточками.
- Навигационные линии/узлы допустимы для реального процесса согласования. Не добавлять
  фиктивные KPI, графики, аналитические панели и декоративные диаграммы.
- Тёмная панель — редкий смысловой акцент. Рабочие экраны не превращать в лендинги.
- Запрещены purple/blue gradients, glassmorphism, случайные 3D-объекты, одинаковые
  скруглённые карточки и неадаптированные shadcn-композиции.

На зелёных кнопках и тёмных панелях — ivory. Декоративная линия не заменяет контрастную

Скругления: 6 px у контролов, 12 px у обособленных панелей. Тени только для перекрывающих
слоёв. Не применять panel-radius и тень автоматически ко всем секциям.

## 3. Типографика

Manrope Variable — интерфейс и заголовки; IBM Plex Mono 400 — индексы, даты,
технические подписи и короткие коды. Шрифты поставляются пакетами Fontsource,
отдаются локально через Vite с font-display swap. Внешнего CDN нет.
Unicode-подмножества включают Cyrillic Extended; RU/KZ проверять визуально, особенно
`Ә Ғ Қ Ң Ө Ұ Ү Һ І`. Mono не использовать для длинных абзацев.

| Уровень | Размер | Начертание | Интерлиньяж |
| --- | --- | --- | --- |
| Display | 40–104 px, fluid | 500 | 1.08 |
| Заголовок страницы | 32–64 px, fluid | 500 | 1.15 |
| Раздел | 22–32 px, fluid | 600 | 1.25 |
| Основной текст | 16 px | 400 | 1.6 |
| Вторичный текст | 14 px | 400–600 | 1.5–1.6 |
| Техническая подпись | 12 px | Mono 400 | 1.5 |

Display — для редких входных композиций, не для каждой рабочей формы.
Не уменьшать основной текст ради плотности. Не фиксировать высоту текстовых блоков.
Заголовки допускают отрицательный tracking, основной текст — нет. Один h1 на экран.
Даты/числа форматировать через Intl при реализации. Не собирать предложения из
фрагментов строк. Текущий язык RU; архитектура должна допускать KZ.

## 6. JANA MOTION / SIGNAL & FLOW

Подтверждённое действие создаёт сигнал и видимый результат. Motion for React отвечает
за UI, GSAP + useGSAP — за intro и Living Route. Общий GSAP chunk загружается
с этими сценами. ScrollTrigger, canvas, WebGL и новые зависимости не добавляются.

| Уровень | Длительность | Применение |
| --- | --- | --- |
| Fast | 160 ms | Hover/focus, цвет и небольшое состояние |
| Standard | 260 ms | Появление блока, локальный переход |
| Expressive | 600 ms | Маска заголовка, прорисовка участка SVG |
| Signature | около 1160 ms | Одна законченная последовательность Living Route |

Кривая `cubic-bezier(0.22, 1, 0.36, 1)`. CSS значения — tokens.css, значения в секундах
для Motion/GSAP — styles/motion.ts; менять согласованно. Появление: opacity и максимум
8–16 px перемещения. Не анимировать весь экран каскадом. Предпочитать transform и
opacity; избегать layout thrashing и анимации width/height больших областей.
Не задерживать ввод или важный результат ради эффекта.

Spring: stiffness 430, damping 38, mass 0.8 — для moving indicator навигации и
сегментированных переключателей. Все основные параметры находятся в `styles/motion.ts`.

### Living Route

`features/leave/motion/routeGeometry.ts` задаёт геометрию SVG и нативных кнопок станций.
SVG рисует линию и одиночный сигнал; HTML даёт доступные названия и карточку этапа.
Ниже 768 px используется отдельная вертикальная геометрия. Станции доступны через
Tab/Enter/Space; выбор показывает пояснение, не меняет бизнес-статус.

Триггер — ID сохранённого события. UI не записывает данные, не меняет статус по
onComplete и не запускает успех по клику submit. Статус доступен сразу. Новый участок
рисуется 600 ms; с 200 ms сигнал проходит его через getPointAtLength; на 720 ms
откликается станция; на 900 ms раскрывается карточка. Новое событие истории проявляется
с 960 ms. Rejected использует отдельную ветку, orange, × и явный текст отказа.

В памяти приложения хранятся до 300 показанных ID на зрителя. Переход в кабинет или
обратно не повторяет событие. Отметка делается при старте timeline, чтобы StrictMode
не поглощал первый показ. IntersectionObserver ждёт видимости геометрии, не блокируя
контролы. Смена события, breakpoint, reduced motion и unmount очищают сцену через
useGSAP/revertOnUpdate и matchMedia.revert. Reduced motion сразу показывает конечное
состояние без сигнала; возврат обычного motion не повторяет событие.

### Общие примитивы

- PageTransition меняет только Outlet: выход 160 ms, вход 260 ms со сдвигом 8 px.
  Ключ — pathname; статус не анимирует всю страницу. Уходящий экран inert/aria-hidden,
  вложенный Suspense сохраняет AppShell и навигацию.
- WorkspaceHeading раскрывает крупный заголовок маской без прыгающих букв.
- AnimatedValue сменяет фактическое число/статус без вымышленных промежуточных сумм.
- SegmentedControl использует native radio и scoped LayoutGroup; Motion перемещает
  только индикатор. При reduced motion layout-анимация не подключается.
- FlowProgress принимает реальное значение и максимум; у маршрута — этап 2/3 или 3/3.
  Примитив подготовлен для будущего обучения, Academy остаётся отдельной задачей.
- Button двигает содержимое на 1 px; навигация получает underline и общий feedback.
- NotificationSignal появляется для существующего непрочитанного уведомления,
  закрывается явно, не крадёт focus и не помечает его прочитанным автоматически.

GSAP владеет dashoffset, сигналом, кольцом станции и внешней оболочкой карточки.
Motion владеет внутренней сменой карточки. React владеет данными и геометрией.
Два движка не анимируют один и тот же transform.

`MotionConfig reducedMotion="user"` задаёт глобальную политику. Reveal дополнительно
обнуляет длительность и не скрывает содержимое изначально при reduced motion.
CSS media query убирает переходы. Для GSAP использовать `gsap.matchMedia()` с
`prefers-reduced-motion`, `useGSAP({ scope })`, cleanup/matchMedia.revert и contextSafe
для отложенных callback. Не допускать конкуренции CSS, Motion и GSAP за одно свойство.
Запрещены постоянные циклы, scroll hijacking, анимация всех карточек и бесконечный pulse.

### Intro входа

Одна последовательность около 0.81 секунды: линии SVG → маски строк заголовка →
появление формы → одиночный проход светлого акцента по CTA. Движение каждого
элемента короткое; форма всё время доступна, нет overlay или задержки submit.
`useGSAP` ограничивает селекторы корнем LoginPage; matchMedia/revert очищает timeline
и media listeners. В StrictMode cleanup безопасен. Intro играет один раз за время
жизни приложения, не повторяется после выхода/смены роли; перезагрузка начинает новую
сессию показа. При reduced motion все элементы сразу статичны.

### Login и AppShell

Вход: асимметрия ivory/editorial слева и тёмной SVG-панели справа. Три строки крупного
заголовка со смещённой последней строкой; выбор роли — нативная radio-группа. Схема
содержит три осмысленных маршрута, станции, координатные подписи и центральный узел
«ВЫ». Это навигационная иллюстрация, не телеметрия и не реальные данные.

При ширине меньше 768 px сначала показываются текст и вход, затем отдельная схема;
технические координаты убраны, подписи станций укрупнены. Никакого уменьшенного
десктопа внутри узкого viewport. На desktop shell использует sidebar 248 px и гибкую
рабочую область. Ниже 1024 px sidebar заменяется нижней навигацией и нативным dialog
со всеми разделами. Dialog удерживает focus, закрывается Escape и возвращает focus.
Меню профиля — раскрывающаяся панель с обычными tab-переходами, без ложного role=menu.

Активный маршрут — тёмная поверхность, mint-иконка и тонкая боковая метка. Второстепенные
пункты спокойные. Семантические дополнения: `--text-inverse-muted`, `--border-inverse`,
`--diagram-grid` и `--surface-navigation`. Светлые текстовые пары не заменять тусклыми
декоративными цветами схемы.

## 7. Развитие и проверка

### Рабочий сценарий отпуска

Форма использует две колонки: период и комментарий слева, тёмный предпросмотр
с будущим маршрутом справа. На мобильном — последовательный поток, нативные
даты и полноширинные контролы. Тестовый баланс обозначается явно. Подтверждение
отправки — нативный dialog без задержки и без вымышленного серверного прогресса.

Jana Flow Map — смысловой тёмный акцент: Submitted отмечает активную станцию
руководителя; Approved завершает маршрут; Rejected обозначает отказ текстом
и знаком ×. Уведомление — последняя станция, факт прочтения хранится отдельно.
На мобильном станции располагаются вертикально. История ниже — вертикальная
шкала фактически сохранённых событий. Новое решение продолжает только новый участок.

Кабинет использует открытые секции с тонкими линиями и типографический баланс,
а реестр — рабочую таблицу. Тёмная панель и таблица не превращаются в ряд карточек.

Следующие этапы задаются отдельно. Проверка: TypeScript strict, lint, production build;
при доступном браузере — 320/768/1440 px, keyboard-only, zoom, focus и reduced motion.
Тесты добавлять для появившегося поведения, а не ради покрытия текстовых заглушек.

`tests/motion.spec.ts`: движение пути/сигнала, отсутствие replay, тёплый отказ,
уведомления, reduced motion на лету, быстрые переходы, очистка GSAP, неизменность shell.
Скриншоты: `artifacts/screenshots/signal-*`. Короткий замер интервалов кадров в headless
Chrome: `artifacts/performance/living-route.json`. Это локальный instrumented-замер,
не гарантия 60 FPS на других устройствах.

Основания: [Tailwind + Vite](https://tailwindcss.com/docs/installation/using-vite),
[theme variables](https://tailwindcss.com/docs/theme),
[Motion accessibility](https://motion.dev/docs/react-accessibility),
[GSAP + React](https://gsap.com/resources/React/).
