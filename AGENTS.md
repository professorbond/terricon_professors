# JanaМен — постоянные инструкции

## Границы задачи

Работать внутри этого репозитория. Сначала читать текущую задачу, этот файл,
`docs/DESIGN_SYSTEM.md` и `docs/SCREEN_MAP.md`. Сохранять рабочий код и чужие изменения.
Выполнять только согласованный этап: не переходить к следующим экранам, backend,
деплою или внешним интеграциям без соответствующей задачи. Текущий результат —
экран демо-входа, AppShell и сквозной отпускной сценарий с mock-сервисами. Academy,
AI Jana и HR-разделы остаются заглушками до отдельных заданий.

## Продукт

JanaМен — рабочая внутренняя HR-платформа. Главный сценарий: сотрудник подаёт заявку
на отпуск → руководитель согласовывает → сотрудник видит результат, историю и
уведомление. Роли: `Employee`, `Manager`, `HRAdmin`. Manager и HRAdmin также могут
иметь личный кабинет; доступ к чужим данным определяется отдельными серверными правами.

Не добавлять фиктивную авторизацию, выдающую себя за безопасную. UI-проверки ролей
не заменяют серверную авторизацию. Официальные кадровые данные read-only.
Использовать только вымышленные данные. Не хранить секреты в Git, Vite env или браузере.
AI Jana отвечает по разрешённой базе знаний с источниками; при отсутствии сведений
честно сообщает об этом и предлагает обратиться в HR. AI не принимает кадровых решений.

## Архитектура

- React + TypeScript + Vite, strict mode обязателен. Не отключать проверки ради сборки.
- Tailwind CSS v4 + CSS custom properties + авторские компоненты; без UI kit по умолчанию.
- `app` — провайдеры и маршруты, `layouts` — оболочки, `pages` — сборка экранов.
- `features` — UI/модели сценариев, `components` — повторно используемые примитивы.
- `services` — контракты/транспорт, `mocks` — явные demo-адаптеры, `styles` — токены.
- Не превращать App.tsx в монолит. Не делать fetch, auth и storage внутри UI-примитивов.
- Не импортировать mocks в продуктовые компоненты; выбирать адаптер в composition root.
- Новая зависимость требует конкретной задачи. Пока не нужны store, form library,
  query cache, UI kit и backend framework. Использовать существующий npm lockfile.
- По мере роста экранов добавлять route-level lazy imports; не делить код искусственно.
- Даты отпуска хранить календарными датами, timestamp событий — с зоной. Не придумывать
  правила подсчёта отпускных дней и официальные кадровые политики.
- Сценарий отпуска использует единое `jana.mock-state.v1` в localStorage. Решение,
  событие и уведомление записывать вместе; проверять команду, статус и expectedVersion
  внутри сервиса. Не добавлять искусственную задержку. Mock-проверки не являются защитой API.
- Демо-расчёт явно обозначен: календарные дни включительно, исходный остаток 24 дня,
  уменьшается только после Approved. Новые кадровые правила требуют отдельной задачи.

## JANA FLOW

Human-Centered Operations Interface: Swiss typography, editorial hierarchy,
навигационные схемы и профессиональные операционные интерфейсы. Это продукт,
а не маркетинговый лендинг. Применять палитру и сетку из DESIGN_SYSTEM.

Запрещены типовой AI SaaS dashboard, синие/фиолетовые градиенты, стеклянные карточки
повсюду, случайные 3D-объекты, бессмысленные графики, одинаковые карточки на всех
экранах, стандартные shadcn-композиции, lorem ipsum и постоянная анимация элементов.

Использовать крупную типографику там, где она помогает иерархии; плотные рабочие
данные не превращать в декоративные заголовки. Группировать отступами, линиями и
типографикой, а не автоматически помещать всё в карточки. Orange — редкий акцент.
Применять semantic tokens, не произвольные цвета Tailwind. Иконки — Lucide React.

## Доступность и motion

- Семантический HTML, один h1 на экран, настоящие button/link/label.
- Клавиатура, видимый focus, skip link, корректный focus после переходов и в диалогах.
- Интерактивная область минимум 44 × 44 px; текстовые ссылки допустимы в строке текста.
- Состояния не различать только цветом. Контраст текста проверять на фактическом фоне.
- Сохранять читаемость на 320 px, 768 px, 1440 px и при увеличении текста/масштаба.
- RU — текущая локаль. Готовить тексты к RU/KZ: не собирать предложения конкатенацией,
  учитывать длину переводов и казахские символы, не встраивать важный текст в изображения.
- Motion — короткие переходы UI; GSAP/useGSAP — только обоснованные timelines.
- Один движок владеет конкретным анимируемым свойством. Scope и cleanup обязательны.
- JANA MOTION / SIGNAL & FLOW: токены в `styles/motion.ts` и `styles/tokens.css`.
  Signature запускается по сохранённому событию, не по оптимистичному клику. Для
  отказа — тёплая ветка, не зелёный успех. Не связывать бизнес-запись с onComplete.
  Смена статуса не должна анимировать всю страницу. Сохранять useGSAP cleanup,
  отсутствие replay при навигации и клавиатурную доступность станций.
  Reduced motion сразу показывает конечное состояние. Не заявлять 60 FPS без замера.
- Уважать prefers-reduced-motion в CSS, Motion и GSAP; без бесконечных циклов, scroll hijack
  и задержки доступа к формам. Не подключать GSAP глобально без нужного сценария.

## Проверка и передача

Перед завершением запускать `npm run check` (lint + TypeScript + production build).
Для изменений входа и оболочки также запускать `npm run test:e2e`: Playwright проверяет
роли, клавиатуру, мобильное меню, reduced motion, переполнение и ошибки консоли.
Playwright MCP при отсутствии подключения заменяется локальным Playwright Test;
это ограничение явно указывать. Скриншоты сохраняются в `artifacts/screenshots/`.
Проверять затронутые пользовательские сценарии по мере их появления. Писать тесты
для бизнес-правил, прав доступа и важных переходов, не ради покрытия простых заглушек.
При изменении визуального UI использовать доступный браузер для desktop/mobile и
клавиатуры; если инструмент отсутствует, честно указать границу проверки.

Проверять актуальные API через Context7/официальные docs. Использовать Playwright MCP
и Figma MCP, если подключены и нужны задаче; недоступность не скрывать.
Обновлять карту экранов и дизайн-документацию при изменении принятых решений.
В отчёте указывать результат, проверки и оставшиеся ограничения. Не заявлять backend,
авторизацию, интеграции и реальные HR-операции реализованными, пока это не так.
